# 遥操作控制模块说明

## 1. 固定结论

当前已经跑通的键盘遥操作链路统一使用 C++，正式控制代码以项目根目录为唯一来源：

```text
键盘读取
-> KeySnapshot
-> makeJogRequests()
-> RobotJogController
-> RobotSdkApi
-> Inexbot SDK
-> TCP 6001
-> 机器人控制器
```

`keyboard_jog_demo_win/` 只保留 Windows 兼容构建入口，不再维护第二套机器人控制逻辑。

## 2. 文件职责

## 3. 对其他上位机公开的主要接口

头文件：`include/robot_control/robot_jog_controller.h`

### 建立连接

```cpp
InexbotSdkApi sdk;
RobotJogController robot(sdk);

robot.connect("192.168.1.13", "6001", controllerMessageCallback);
```

连接函数不会额外创建 TCP 探测连接，避免占用只允许单会话的 6001 端口。

### 完整进入遥操作状态

```cpp
JogSessionConfig config;
config.speedPercent = 10;
config.coordinate = 1;          // 直角坐标
config.restartIfRunning = true; // 已上电时先下电，再重新上电

const bool ok = robot.enterTeachJog(config, [] {
    return applicationWantsToExit();
});
```

只有 `enterTeachJog()` 返回 `true` 后，界面才允许发送点动命令。

### 开始和停止点动

```cpp
robot.startJog({1, true}); // X+
robot.stopJog(1);          // 停止 X

robot.startJog({2, false}); // Y-
robot.startJog({3, true});  // Z+
robot.stopAllJogging();
```

需要做关节点动时先切换点动坐标系，再使用相同的开始/停止接口：

```cpp
robot.setJogCoordinate(0); // 关节坐标
robot.setJogSpeedPercent(5);
robot.startJog({6, true}); // J6+
robot.stopJog(6);
```

GR270 为六轴机械臂，正常使用轴号 1..6；接口保留厂商 SDK 的第 7 个本体轴位，但不得在 GR270 上把轴 7 当作真实关节使用。

当前轴号约定：

| 轴号 | 直角坐标方向 |
|---:|---|
| 1 | X |
| 2 | Y |
| 3 | Z |

`robot_start_jogging()` 是保持型点动命令。上层按住按键期间每 100 ms 重发，松键、换向、异常和退出时立即调用停止。

### 单次和循环清错

```cpp
robot.clearErrorOnce();

robot.clearErrorUntilReady([] {
    return applicationWantsToExit();
});
```

单次清错只表示发送一次 `clear_error`。循环清错会持续读取真实伺服状态，只有到达 `Ready(state=1)` 或 `Running(state=3)` 才返回成功。

### 关节目标位置控制

```cpp
JointMoveCommand command;
command.targetDegrees = {0.0, -20.0, 35.0, 0.0, 45.0, 0.0, 0.0};
command.axisCount = 6;
command.velocityPercent = 10.0;
robot.moveJoints(command);
```

该接口调用厂商 `robot_movej`，是目标位置控制；`velocityPercent` 的单位是百分比。发送前要求伺服为 `Running(state=3)`，且没有活动点动轴。

### XYZ 直线位置控制

```cpp
CartesianXyzCommand command;
command.xMillimeters = 500.0;
command.yMillimeters = 0.0;
command.zMillimeters = 600.0;
command.velocityMillimetersPerSecond = 20.0;
robot.moveCartesianXyz(command);
```

该接口先调用 `get_current_position` 读取当前 7 个直角坐标值，只替换 X/Y/Z，保持姿态和第 7 位不变，再调用厂商 `robot_movel`。直线速度单位是 mm/s，不是百分比。首次真机使用必须低速验证厂商控制器返回数组的坐标顺序。

### 运行中状态恢复

```cpp
int state = -1;
if (!robot.getServoState(state)) {
    // 通信失败：停止主循环并进入 shutdown。
}

if (state != static_cast<int>(ServoState::Running)) {
    robot.recoverRunningServo(exitRequested);
    // 恢复后必须清空旧输入，要求操作者重新按键。
}
```

错误/警告回调只允许记录日志，不能在回调线程里调用清错、上下电或运动函数。运行安全判断只使用主动查询到的伺服状态。

### 正确退出

```cpp
robot.shutdown();
// 或使用语义相同的安全断开入口：
robot.disconnect();
```

`shutdown()` 是幂等接口，也会由析构函数兜底调用。固定顺序如下：

```text
停止所有活动点动轴
-> 如果本会话负责上电，则执行下电
-> 等待伺服回到 Ready
-> 如果进入程序前为 Stopped，则恢复 Stopped
-> 恢复进入程序前的操作模式
-> 断开 SDK
```

窗口关闭、Esc、Ctrl+C、键盘断开、SDK 发送失败和伺服状态异常最终都必须进入该流程。

## 4. 上电、下电、清错和模式切换

### 上电流程

键盘点动使用示教模式，不使用远程模式：

```text
connect
-> get_current_mode（保存原模式）
-> set_current_mode(0)（示教）
-> set_teach_type(0)（点动）
-> get_servo_state
-> 必要时 clear_error
-> set_servo_state(1)（Ready）
-> set_servo_poweron
-> 连续 3 次确认 state=3
-> set_current_coord(1)
-> set_speed
-> 开放点动
```

如果进入程序时已经是 `state=3`，当前已验证策略是先执行一次下电，再从 `state=1` 重新上电。状态稳定确认完成后不得再次进入该初始重启分支，否则会造成循环上下电。

### 清错流程

```text
检测到 state=2
-> 禁止发送任何点动
-> clear_error
-> 尝试 set_servo_state(1)
-> 再次读取真实 state
-> 未恢复则继续循环
-> 恢复后重新完成上电确认
```

`clear_error()` 返回成功只表示清错请求被接收，不代表报警已经解除；必须继续读取 `get_servo_state()`。

### 下电流程

```text
stopAllJogging
-> set_servo_poweroff
-> 等待 state=1
```

禁止在仍有活动点动命令时直接断开连接。

### 模式切换

```cpp
robot.setMode(RobotMode::Teach);  // 0，键盘点动
robot.setMode(RobotMode::Remote); // 1，远程 IO/程序控制
robot.setMode(RobotMode::Run);    // 2，作业运行
```

模式切换和运动范式必须分开设计：

- 键盘遥操作：`robot_start_jogging/robot_stop_jogging`。
- 单点位置运动：`robot_movej/robot_movel`。
- 轨迹队列：`queue_motion_*`。
- 作业文件：`job_*`。

不同运动范式的暂停、继续、停止和完成判断不能共用一个没有语义区分的函数。

## 5. 后续增加新函数的固定方法

以增加“读取当前位置”为例：

1. 在 `include/robot_control/robot_sdk_api.h` 的 `RobotSdkApi` 中增加抽象函数。
2. 在 `InexbotSdkApi` 中声明同名实现。
3. 在 `src/robot_control/robot_sdk_api.cpp` 中调用厂商 SDK 原函数。
4. 在 `include/robot_control/robot_jog_controller.h` 中增加提供给上位机的安全接口。
5. 按功能选择 `src/robot_control/` 下对应的小型 `.cpp`；新运动类型使用新的独立 `.cpp`，不要重新堆回会话文件。
6. 在 `FakeRobotSdk` 中实现测试桩，并在测试中验证调用顺序和失败分支。
7. `apps/keyboard_jog_demo.cpp`、Qt、ROS2 或其他上位机只调用 `RobotJogController`，不直接调用厂商 SDK。

禁止直接修改厂商 SDK 头文件、`.so`、`.dll` 或 `.lib`。

## 6. 当前封装评价

整理后已经形成三层边界：

```text
界面/键盘层
-> 安全控制流程层 RobotJogController
-> 厂商适配层 RobotSdkApi
```

这套边界可以直接复用于后续 Qt、ROS2 或其他 C++ 上位机。Python 上位机若需要复用，建议在 `RobotJogController` 外再增加 pybind11/C API 桥接，不要在 Python 中重新复制一套清错和上下电状态机。

目前仍需真机继续验证的项目：断网时停止效果、急停恢复、控制器重启、Windows 窗口强制关闭、各轴方向和最大允许速度。

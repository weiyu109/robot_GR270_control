# 新机械臂终端调试标准流程

## 1. 这种调试方式叫什么

本项目采用的是：

> **终端优先（CLI-first）的分层机械臂调试程序**

它不是完整上位机界面，而是先用一个小型 C++ 控制台程序打通最短控制链路：

```text
终端参数/键盘
-> 输入映射层
-> 机器人安全控制层
-> 厂商 SDK 适配层
-> 控制器 IP:端口
-> 机械臂
```

这种方式适合新机械臂首次接入，因为终端日志直接、依赖少、容易定位故障。链路验证稳定后，再把相同的控制类接入 Qt、ROS2、Python 或其他上位机。

## 2. 固定目录分类

新机械臂项目建议统一采用下面的目录结构：

```text
robot_terminal_demo/
├── apps/                         # 可执行程序入口，只编排流程
│   ├── keyboard_jog_demo.cpp     # 连接真机的键盘遥操作入口
│   └── keyboard_input_test.cpp   # 不连接机械臂的键盘诊断入口
├── include/
│   ├── input/                    # 输入层公共头文件
│   └── robot_control/            # 上位机可调用的机器人公共接口
├── src/
│   ├── input/                    # Linux/Windows 键盘读取和按键映射
│   └── robot_control/
│       ├── common/               # 公共状态检查、错误输出
│       ├── connection/           # 连接、断开连接
│       ├── mode/                 # 示教/远程/运行模式切换
│       ├── safety/               # 清错、循环清错、上下电、报警恢复
│       ├── jog/                  # 轴速度/持续点动控制
│       ├── motion/               # 关节、XYZ、轨迹位置控制
│       ├── session/              # 完整启动和退出流程编排
│       └── sdk/                  # 厂商 SDK 的薄适配层
├── tests/                        # 不连接真机的模拟 SDK 回归测试
├── docs/                         # 中文流程、接口和迁移说明
├── vendor/ 或 厂商SDK目录/       # 原始 SDK；不要直接修改
└── CMakeLists.txt
```

### 文件职责规则

1. `apps/` 不直接调用厂商 SDK，只调用机器人控制类。
2. `sdk/` 只做厂商函数转发，不编写复杂状态机。
3. `safety/` 负责清错、上下电和安全恢复。
4. `jog/` 只负责按下开始、松开停止的持续运动。
5. `motion/` 负责 `MoveJ`、`MoveL`、轨迹队列等目标运动。
6. 每个 `.cpp` 只保留一种功能类别。
7. 每个公开函数前写中文注释，明确前置状态、单位、是否会运动、失败结果。
8. 新功能先增加模拟 SDK 测试，再连接真机验证。

## 3. 固定功能分类

| 功能 | 推荐函数 | 是否会运动 |
|---|---|---:|
| 连接 | `connect(ip, port)` | 否 |
| 断开 | `disconnect()` | 否，但应先停止和下电 |
| 状态查询 | `getServoState()`、`printState()` | 否 |
| 模式切换 | `setMode()` | 否 |
| 单次清错 | `clearErrorOnce()` | 否 |
| 循环清错 | `clearErrorUntilReady()` | 否 |
| 伺服就绪 | `setServoReady()` | 否 |
| 上电 | `powerOnOnce()` | 通常不产生位移，但已进入可运动状态 |
| 下电 | `powerOff()` | 停止运动并关闭伺服 |
| 轴点动 | `startJog()`、`stopJog()` | 是，持续速度式运动 |
| 关节位置 | `moveJoints()` | 是，目标位置运动 |
| XYZ 位置 | `moveCartesianXyz()` | 是，直线目标位置运动 |
| 自动恢复 | `recoverRunningServo()` | 可能重新上下电，不应自动恢复旧运动 |
| 安全退出 | `shutdown()` | 停止、下电、恢复模式、断开 |

## 4. 新机械臂调试顺序

必须按以下顺序逐级验证，不要第一次运行就直接发送运动指令。

### 第 0 阶段：确认 SDK

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

确认 SDK 头文件、动态库、CPU 架构和编译器版本匹配。

### 第 1 阶段：只测试键盘

```bash
./build/keyboard_input_test --list
./build/keyboard_input_test /dev/input/by-id/实际键盘-event-kbd
```

这一阶段禁止连接机械臂。确认按下和松开事件都能检测到，尤其要验证松键停止事件。

### 第 2 阶段：只连接和查询

程序只执行：

```text
connect
-> 查询模式
-> 查询伺服状态
-> 打印状态
-> disconnect
```

不要清错、不要上电、不要运动。先确认 IP、端口和 SDK 通信正常。

### 第 3 阶段：清错和上下电

固定流程：

```text
查询真实伺服状态
-> state=2 时循环清错
-> 切换到 Ready(state=1)
-> 单次上电
-> 连续多次确认 Running(state=3)
-> 单次下电
-> 确认回到 Ready(state=1)
```

如果启动前已经上电，应先停止运动并下电，再从 Ready 状态重新上电，避免状态归属不清。

### 第 4 阶段：单轴低速点动

满足以下条件后才开放点动：

- 工作区已清空；
- 急停可随时触达；
- 速度设置为较低值，例如 3%～5%；
- 已确认轴号、正负方向和坐标系；
- 松键、Esc、Ctrl+C 和窗口关闭都能进入停止流程。

第一次只测试一个轴、一个方向、短时间点动。确认停止有效后再测试其他轴。

### 第 5 阶段：关节和 XYZ 位置运动

位置运动前必须确认：

- 角度单位是度还是弧度；
- 直角坐标单位是 mm 还是 m；
- 姿态顺序是 RX/RY/RZ、四元数还是厂商自定义格式；
- 速度是百分比、度每秒、mm/s 还是其他单位；
- `MoveJ`、`MoveL` 的同步/阻塞语义；
- 到位、暂停、停止和超时的判断函数。

不要凭其他品牌机械臂经验猜测参数顺序，必须以当前厂商 SDK 头文件和真机手册为准。

## 5. 标准运行命令模板

Ubuntu 示例：

```bash
cd /你的项目路径

KEYBOARD_DEVICE="$(readlink -f /dev/input/by-id/*你的键盘标识*-event-kbd)"

./build/keyboard_jog_demo \
  机械臂控制器IP \
  SDK端口 \
  点动速度百分比 \
  "$KEYBOARD_DEVICE"
```

当前 GR270 项目的实际命令：

```bash
cd ~/wydata/keyboard_jog_demo

KEYBOARD_DEVICE="$(readlink -f /dev/input/by-id/*ITE*8910*-event-kbd)"

./build/keyboard_jog_demo \
  192.168.1.13 \
  6001 \
  10 \
  "$KEYBOARD_DEVICE"
```

## 6. 固定安全退出流程

所有退出路径必须汇合到同一个幂等函数：

```text
禁止发送新运动
-> 停止全部活动点动轴
-> 停止位置/队列运动（如果对应 SDK 支持）
-> 本会话负责上电时执行下电
-> 等待伺服回到安全状态
-> 恢复进入前模式（如果需要）
-> 断开 SDK
```

以下事件都必须进入该流程：正常退出、Esc、Ctrl+C、窗口关闭、键盘断开、SDK 发送失败、伺服异常和网络异常。

不建议为了下电单独创建一个长期运行线程。更可靠的方式是：主控制对象保存状态，所有退出路径调用同一个 `shutdown()`；状态监控线程只发出停止请求，不直接与主线程并发上下电。

## 7. 以后交给 Codex 的固定指令

接入另一台机械臂时，可以把下面这段指令直接发送给 Codex，并替换方括号内容：

```text
请按照“终端优先的分层机械臂调试流程”接入 [机械臂型号]。

控制器 IP：[IP]
SDK 端口：[端口]
厂商 SDK 路径：[SDK路径]
系统平台：[Ubuntu/Windows]

要求：
1. 先阅读厂商 SDK 头文件，确认连接、断开、模式、状态、清错、上下电、点动、停止、MoveJ、MoveL 的真实函数和参数单位，不允许猜测。
2. 先建立不连接机械臂的键盘测试和模拟 SDK 单元测试。
3. 代码按 common、connection、mode、safety、jog、motion、session、sdk 分类。
4. 每个 cpp 只放一种功能类别，每个公开函数前增加中文注释。
5. apps 入口不得直接调用厂商 SDK，必须经过统一 RobotController 接口。
6. 调试按“键盘 -> 连接查询 -> 清错上下电 -> 单轴低速点动 -> 关节/XYZ位置”的顺序逐级开放。
7. Esc、Ctrl+C、窗口关闭、通信失败和状态异常必须统一进入停止、下电和断开流程。
8. 未得到真机运动授权前，只允许编译、模拟测试、连接和只读状态检查，不发送运动指令。
9. 完成后给出构建命令、运行命令、文件分类表、函数调用链和仍需真机验证的风险。
```

## 8. 每次接入完成的验收清单

- [ ] 无机械臂时键盘按下/松开检测通过；
- [ ] 模拟 SDK 测试覆盖启动和退出顺序；
- [ ] 连接失败不会尝试上电；
- [ ] 报警未解除时不会开放运动；
- [ ] 上电前真实状态为 Ready；
- [ ] 只有稳定确认 Running 后才允许运动；
- [ ] 松键立即停止对应轴；
- [ ] 状态异常先停止运动，不自动恢复旧按键；
- [ ] Esc、Ctrl+C 和窗口关闭执行安全退出；
- [ ] 轴号、方向、单位和坐标系已低速真机验证；
- [ ] 构建、测试和运行命令已经写入 README；
- [ ] 厂商 SDK 原始文件没有被修改。
